# HU-01: Proteger el token de autenticación

## Origen
- **H-AUTH-03 (auth):** `auth/src/main/java/com/bcp/workshop/auth/LegacyTokenUtil.java:8,13-15`. El token está codificado en Base64, incluye un secreto fijo y no tiene firma; Base64 no acredita su integridad.
- **H-AUTH-05 (auth):** `auth/src/main/java/com/bcp/workshop/auth/LegacyTokenUtil.java:8`; `auth/src/main/resources/application.properties:4-7`. El secreto del token está fijado en Java y CORS acepta orígenes mediante una expresión global.

## Contexto
El token actual no acredita la integridad de sus datos. Además, el secreto está fijado en el código y la política CORS usa una expresión global, lo que dificulta su rotación y la restricción de orígenes.

## Ajustes necesarios
- Sustituir el token que solo codifica datos por uno cuya integridad pueda verificarse.
- Retirar el secreto del código y permitir su configuración externa, sin incluir valores sensibles en el repositorio ni en la evidencia.
- Restringir CORS a los orígenes permitidos mediante configuración, en lugar de aceptar orígenes con una expresión global.

## Criterios de aceptacion
- Una prueba verifica la integridad de un token generado y falla si sus datos se alteran.
- Una prueba rechaza un token cuya integridad no pueda verificarse.
- Una comprobación del código confirma que `LegacyTokenUtil` no contiene el secreto del token fijado directamente.
- Una prueba de configuración confirma que un origen permitido puede interactuar con el servicio y que un origen no permitido es rechazado.

## Evidencia esperada
- Componente: **auth**. Resultados de pruebas para integridad y rechazo de tokens alterados o no verificables, asociados a **H-AUTH-03**.
- Componente: **auth**. Revisión o comprobación de que el secreto no está fijado en código, más resultados de pruebas de orígenes CORS permitidos y no permitidos, asociados a **H-AUTH-05**.
- Salida de las pruebas ejecutadas y referencias a los archivos de código/configuración modificados; no adjuntar secretos ni valores de tokens.
